# Extended workspace interaction design

This pass extends the established PDF Master tokens and shell before implementing the generation, education, commerce and editing views. It addresses the user's request for complete local demonstrations while keeping locally simulated providers/payments explicit.

## Navigation and modes

Desktop adds Create, Study & teaching, Projects and Editor only when their server capabilities exist. Templates and saved workflows are reached from Tools and the creation studio. Mobile retains Home, Tools, Tasks, Account; Tools contains entry cards for the new surfaces. No staff interface enters this repository.

## Generation / education

Create → choose released capability → supply topic, own text or private files → explicit output language/format and length → create draft → generate outline → review/edit/reorder sections → server quote → confirm → existing job/result page. The local deterministic fixture provider has a persistent visible notice explaining that it formats supplied content and fixtures; it never masquerades as a live model. Draft version conflicts remain visible and cannot silently overwrite edits.

Student/school/teacher tabs filter server configuration without creating new accounts or entitlements. Shared form fields collect topic/subject/grade/objectives instead of personal child information. Saved projects require explicit consent and show the 90-day expiry. Practice reveals reviewed answers only after submission. Teacher results keep learner materials separate from teacher keys. Share buttons appear only for API-authorized learner artifacts and offer explicit revocation.

## Editor

Upload or select PDF → persisted editor document → actual authenticated page preview → choose command → position using click/point controls → staged command list → versioned save → quote/export. Coordinates are top-left PDF points. Add text and replace existing text are visibly separate actions. Redaction has its own permanent-removal/rasterization acceptance control. The UI displays export limitations from the server; no black rectangle is represented as completed redaction. Image inputs are ordered, owner-authorized assets.

## Reusable work / billing

Template: name, purpose, locale and structured content, explicit save/delete. Workflow: ordered tool steps with parameter schemas and keyboard reorder; select inputs and obtain quotes before run. Billing reads sandbox mode from the server; sandbox invoices require an explicitly labeled Simulate payment button, with entitlements refreshed only after a confirmed backend transaction. Cancellation preserves paid access until the displayed end date. Referrals show only recorded qualification/reward values and use user-initiated copy.

## Responsive / state coverage

1440: two-column studio/editor with 300px rail; section rows, floating page canvas controls. 390/320: one column, command controls after preview, primary action in normal flow above safe-area navigation. All three locales, light/dark, empty/loading/API error/quota/version conflict/expired asset/pending invoice/provider fixture states are required. Native inputs/buttons and visible focus remain; no drag-only interaction.
